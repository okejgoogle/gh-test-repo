# WARP.md

This file provides guidance to WARP (warp.dev) when working with code in this repository.

## Огляд репозиторію

На момент створення цього файлу репозиторій містить лише файл `README.md` без змістовного контенту. Специфічні інструкції щодо збірки, тестування чи запуску застосунку в репозиторії відсутні.

## Архітектура та структура

- Структура проєкту наразі не визначена, оскільки немає вихідних кодів чи каталогів на кшталт `src/`, `backend/`, `app/` тощо.
- Коли з'являться вихідні файли, варто оновити цей файл, додавши:
  - короткий опис основних модулів та шарів (наприклад, «CLI», «API», «frontend», «ядро доменної логіки»);
  - як вони взаємодіють між собою на високому рівні.

## Команди розробки

Наразі в репозиторії немає типових конфігураційних файлів (наприклад, `package.json`, `pyproject.toml`, `Makefile`, `Dockerfile`), які зазвичай визначають стандартні команди збірки, запуску та тестування.

Рекомендації для майбутніх екземплярів Warp:
- Перед тим як намагатися зібрати чи протестувати проєкт, перевірити, чи з'явилися в репозиторії нові файли конфігурації (через `ls`, перегляд у файловому дереві тощо).
- Якщо будуть додані інструменти збірки/тестування (наприклад, скрипти у `package.json`, цілі у `Makefile`, налаштування `pytest`, `go test` тощо), оновити цей файл і явно задокументувати:
  - як запустити всі тести;
  - як запустити окремий тест або тестовий файл;
  - як зібрати застосунок;
  - як запустити локальне середовище розробки.

## Подальше оновлення WARP.md

Коли в репозиторії з'являться реальні вихідні коди та інфраструктура, слід оновити `WARP.md`:
- описати основні каталоги та модулі (тільки на високому рівні, без переліку кожного файлу);
- додати конкретні команди для збірки, lint-інгу, запуску тестів і локального сервера розробки;
- за потреби коротко включити найважливіші правила з інших файлів (наприклад, `README.md`, `CLAUDE.md`, `.github/copilot-instructions.md`, правила Cursor тощо).
